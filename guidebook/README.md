# คู่มือ CSMJU2030 สำหรับ PL และ AIE

ในโฟลเดอร์ `guidebook` นี้มีคู่มือ 2 เรื่อง แต่ละเรื่องมี 2 ไฟล์:
- 📄 **.pdf** เอาไว้อ่าน
- 📝 **.md** เอาไว้คัดลอกคำสั่ง *(คำสั่งยาว ๆ ใน PDF อาจถูกตัดขึ้นบรรทัดใหม่ คัดลอกไปวางแล้วอาจรันไม่ผ่าน แนะนำให้คัดลอกจากไฟล์ .md แทน)*

---

## 📚 ภาพรวมคู่มือ

### 1️⃣ github-org-guide — ใช้ GitHub ของโครงการยังไง
**เรื่องที่อธิบาย:**
- บทบาทใน org และสิทธิ์ของแต่ละทีม
- เริ่มใช้งานครั้งแรก (รับคำเชิญ, เปิด 2FA, clone repo)
- ขั้นตอนทำงานประจำวัน ตั้งแต่แตก branch จนเปิด PR
- กฎที่ CI บังคับ และรูปแบบชื่อ branch / commit
- การรีวิวและ merge PR
- ขอ repo ใหม่ และขอยกเว้นกฎ
- ปัญหาที่เจอบ่อย และข้อจำกัดของ GitHub plan Free

### 2️⃣ LOCAL_INTEGRATION_GUIDE — รัน 3 ระบบบนเครื่องตัวเอง แล้วทดสอบว่าเชื่อมกันได้
**เรื่องที่อธิบาย:**
- Clone และจัดโฟลเดอร์ให้ตรงมาตรฐาน
- ตั้งค่าและรัน Core Hub · demo-student-subsystem · ระบบของทีมตัวเอง
- ลงทะเบียนระบบของทีมกับ Core Hub
- ทดสอบการเชื่อมต่อ 9 ข้อ + ตรวจด้วย conformance
- ตารางแก้ปัญหา และตารางคำสั่งทั้งหมดที่ใช้ตอน dev
*(ใช้ 4 พอร์ต: 3000 Core Hub · 3100 หน้าเว็บ Core Hub · 3001 demo · 3002 ระบบของทีม)*

## 👷 ลำดับการอ่านสำหรับ AIE
1. **github-org-guide ข้อ 1–3** → อ่านก่อนเริ่มงานวันแรก
2. **LOCAL_INTEGRATION_GUIDE** → ทำตามทีละข้อตั้งแต่ข้อ 1 ถึง 10 (ห้ามข้าม)
3. **github-org-guide ข้อ 4 และ 7** → อ่านก่อนเปิด PR ครั้งแรก
4. **LOCAL_INTEGRATION_GUIDE ภาคผนวก ข** → เก็บไว้เปิดดูระหว่างทำงาน

---

## 🧑‍💼 ลำดับการอ่านสำหรับ PL
1. **github-org-guide ข้อ 1 และ 4** → ภาพรวมบทบาทและกฎที่ CI ตรวจให้แล้ว
2. **github-org-guide ข้อ 5** → ขั้นตอนรีวิวและ merge PR (หน้าที่หลักของ PL)
3. **github-org-guide ข้อ 6 และ 8** → คำขอยกเว้นกฎ (PL ต้องรับรองก่อนส่งต่อ) และข้อจำกัดของ plan Free
4. **LOCAL_INTEGRATION_GUIDE ข้อ 0 · 7 · 10** → ภาพรวมระบบ, การทดสอบ และเช็คลิสต์ (ใช้ตรวจว่างาน AIE ผ่านจริง)

## 💡 ก่อนเริ่มทำงาน
- คำสั่งในคู่มือเขียนแบบ `โฟลเดอร์ >> คำสั่ง`
  - *เช่น* `csmju-core-hub/backend >> pnpm start:dev`
  - แปลว่าให้เข้าไปอยู่ในโฟลเดอร์ `csmju-core-hub/backend` ก่อน แล้วพิมพ์แค่ `pnpm start:dev` (ไม่ต้องพิมพ์ `>>`)
- **วิธีเข้าโฟลเดอร์ที่ง่ายที่สุด:** เปิดใน VS Code → คลิกขวาที่โฟลเดอร์ → `Open in Integrated Terminal`
- **ไม่แน่ใจว่าอยู่ถูกโฟลเดอร์มั้ย?** ให้พิมพ์ `pnpm run` ถ้าไม่เห็นคำสั่งที่จะรันในรายการ แปลว่าอยู่ผิดที่
- **ใช้ `pnpm` เท่านั้น** ห้ามใช้ `npm install` เด็ดขาด (CI จะตีตก เหตุผลอยู่ในภาคผนวก ก)
- **Windows:** ส่วนที่มีป้าย `Git Bash` ต้องรันใน Git Bash นอกนั้นใช้ PowerShell ได้
